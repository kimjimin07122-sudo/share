# dronev2 — 드론 텔레메트리 이상탐지 파이프라인 (구조 요약)

실제로 돌아가는 데 필요한 최소 구성(19개 파일)만 모았습니다. import 의존성까지 확인해서, 이 파일들만 있으면 각 모델을 처음부터 학습·평가할 수 있습니다. 데이터·학습된 가중치·실험 결과/그림은 용량 문제로 뺐습니다.

## 전체 흐름

```
원시 CSV (16채널 센서)
   → preprocessing.py (공통 리샘플·인과적 per-flight 정규화·실제초 윈도우)
   → feature_engineering.py (raw/1차미분/2차미분/에너지)
   → 모델 (networks/) — 재구성 or 예측
   → Isolation Forest로 2차 판단
   → 융합 점수 → 이상 탐지 / 채널별 진단
```

## 모델 4가지 + 각각의 진입점

| 모델 | 구조 (`networks/`) | 학습/평가 진입점 |
|---|---|---|
| VAE (원 논문 재현) | `vae.py` | `train.py` |
| GRU 예측기 | `gru_predictor.py` | `train_gru.py` |
| **LSTM-AE + Isolation Forest** (메인, 재구성 기반) | `lstm_ae.py` | `train_eval_lstm_ae_heldout.py` ⭐ |
| LSTM 예측기 (다음 시점 1개만 예측) | `lstm_predictor.py` | `train_eval_lstm_predictor.py` |
| LSTM 15초 앞 예측기 (교수님 요구: 최소 15초 lead time) | `lstm_predictor.py` (동일 구조 재사용) | `train_eval_lstm_predictor_15s.py`(v1) → `train_eval_lstm_predictor_15s_multisession.py`(v2, v1을 import해서 씀) |

## 공통 지원 모듈 (여러 모델이 같이 씀)

- `config.py` — 채널명, 하이퍼파라미터 등 전역 설정
- `data_loader.py` — StandardScaler
- `gru_data_loader.py` — CSV 로딩 + 실제 타임스탬프 파싱(`read_raw_csv_with_timestamp`, 이름과 달리 GRU 전용 아니고 거의 모든 모델이 씀)
- `feature_engineering.py` — feature 계산
- `preprocessing.py` — 파이프라인 v4(가장 최신 버전, 세션드리프트 근본원인 3가지를 고친 버전)
- `eval.py` — 공통 평가 지표(`compute_binary_metrics` 등)
- `eval_lstm_ae.py` — LSTM-AE 재구성 오차 계산 함수(`train_eval_lstm_ae_heldout.py`가 여기서 import함 — 이름은 "eval_"지만 핵심 의존성)

## 여기 없는 것 (필요하면 요청)

- 연구 과정에서 나온 검증/실험 스크립트 30여 개 (아래 "왜 이렇게 설계했는지"의 근거가 된 실험들 — negative result 포함)
- 온보드 배포 스크립트(ONNX 변환, 스트리밍 검출기, Jetson 벤치마크)
- 데이터셋, 학습된 모델 가중치, 결과 그림

## 왜 이렇게 설계했는지 (핵심 설계 결정의 배경)

### `preprocessing.py`가 왜 이런 모양인가 — 세션드리프트 근본원인 규명

처음엔 AUROC가 0.99+로 잘 나왔는데, 재검증해보니 "진짜 이상 탐지"가 아니라 **"이 파일이 학습 세션과 얼마나 다른가"를 재고 있었음**이 드러났습니다. 학습 파일 기준으로 맞춘 스케일러를 통과시키면 test 파일 feature 값이 학습 대비 최대 380배(46,404 vs 122.6)까지 튀었고, 그래서 모델이 포화돼 재구성 결과와 입력의 상관계수가 겨우 +0.25였습니다. 원인을 파고드니 입력 파이프라인 결함이 3개 겹쳐 있었습니다:

1. **`energy` feature(raw²)가 세션 간 값 차이를 제곱으로 증폭** — OOD(분포 밖) 상위 8개 feature가 전부 `.energy` 계열이었습니다.
2. **per-flight 정규화 누락** — 원 논문(Reis & Reis, Sensors 2025) 6.1절이 "모든 채널을 비행별로 정규화했다"고 명시하는데, 저희는 학습 파일 기준 전역 스케일러를 모든 test 파일에 그대로 적용하고 있었습니다.
3. **윈도우가 "샘플 개수" 기준이라 학습/평가에서 물리적 길이가 다름** — 같은 `window=32`가 학습(~991Hz)에선 32ms, 평가(~250Hz)에선 128ms로 4배 차이 났습니다.

`preprocessing.py`는 이 3가지를 한 번에 고칩니다: 공통 Hz로 리샘플 + 비행별 정규화 + 실제 초 단위 윈도우. 그 결과 세션드리프트가 크게 줄면서도, 이 프로젝트의 핵심 성과(burst 구간에서 mag_x 채널이 정확히 1위로 짚히는 것)는 그대로 유지됐습니다.

추가로, 처음엔 "비행 전체"의 평균/표준편차로 정규화했는데, 이러면 t=100초 시점 데이터가 t=10초 시점 정규화 값에 영향을 줍니다(미래 데이터가 현재에 새는 비인과적 구조) — 온보드 실시간 배포에서는 애초에 불가능한 방식이라, **비행 시작 30초(warmup)만으로 정규화 기준을 잡는 인과적(causal) 방식**으로 다시 고쳤습니다.

### `gru_data_loader.py`에 `read_raw_csv_with_timestamp`가 왜 있나

애초에 `DATA_HZ=10`으로 가정하고 있었는데, 실제로 확인해보니 학습 파일은 ~991Hz, 평가 파일은 ~250Hz로 전혀 다른 값이었습니다(둘의 비율이 정확히 4배). feature 계산에서 미분(속도)을 구할 때 이 잘못된 고정값을 dt로 쓰고 있어서, 서로 다른 세션의 미분 feature 스케일이 체계적으로 어긋나고 있었습니다. 이 함수는 각 CSV의 실제 타임스탬프 컬럼을 읽어서 진짜 dt를 계산해주고, 이제 `preprocessing.py`를 포함해 거의 모든 모델이 이걸 씁니다.

### `train_eval_lstm_ae_heldout.py`가 학습 파일을 왜 85/15로 나누나

원 논문은 학습 파일과 별도로 "정상 테스트 파일" 하나를 더 써서, 모델이 한 번도 안 본 정상 데이터로 이상 판정 임계값을 잡습니다. 저희가 받은 데이터엔 이 파일이 없어서, 학습 파일 뒷부분 15%를 아예 학습에서 빼고 그 부분으로 임계값을 계산합니다 — 학습 파일 전체를 재사용해서 임계값을 잡으면 모델이 이미 본 데이터라 임계값이 낙관적으로(너무 낮게) 잡힐 위험이 있기 때문입니다.

### `eval_lstm_ae.py`를 예측기 스크립트들도 왜 가져다 쓰나

LSTM-AE(재구성)와 LSTM 예측기(다음 시점 예측)는 오차를 만드는 방식만 다르고, 그 뒤(오차를 요약해서 Isolation Forest에 넣고, 두 점수를 융합하고, 채널별로 어디가 이상한지 진단하는) 로직은 완전히 동일합니다. 그래서 이 후처리 로직을 `eval_lstm_ae.py`에 두고 재구성 모델과 예측 모델이 같이 가져다 씁니다.

### 15초 예측기가 v1(`_15s.py`) → v2(`_15s_multisession.py`) 두 단계인 이유

v1은 학습 파일(`x70_all.csv`) 하나만 썼는데, 15초 앞을 내다보는 예측 쌍을 만들다 보니 학습 데이터가 102쌍밖에 안 나와서 오차 스케일이 매우 불안정했습니다(기준선 대비 75배). v2는 나머지 test 파일들도 학습에 섞어서(정상/비정상 라벨 구분 없이 — 짧은 fault가 파일의 극히 일부라 약한 오염으로 간주하는 흔한 근사) 학습 쌍을 841개(8배)로 늘렸고, 오차 스케일 불안정성이 크게 개선됐습니다.

### 모델이 4종류나 있는 이유 (VAE → GRU → LSTM-AE → LSTM 예측기)

순서대로 시도한 것이지 전부 병렬로 쓰는 게 아닙니다:
1. **VAE** — 원 데이터셋 논문 재현. 채널진단(어느 채널이 고장인지 짚기) 실패 — baro_altitude 채널이 항상 1위로 나옴(세션드리프트).
2. **GRU** — TiTAD 논문의 ablation에서 성능 기여가 큰 GRU 예측 브랜치만 채택. 정상/비정상 분리력은 좋아졌지만 채널진단은 여전히 실패.
3. **LSTM-AE** — 드론 데이터·엣지 실측이 있는 논문(Reis & Reis, Sensors 2025)을 재구현. **처음으로 채널진단 성공**(mag_x가 burst 구간에서 정확히 1위).
4. **LSTM 예측기** — 같은 파이프라인을 재구성 대신 다음 시점 예측 방식으로 전환. 이후 교수님이 "최소 15초 앞 예측"을 요구하면서 15초 버전으로 확장.
